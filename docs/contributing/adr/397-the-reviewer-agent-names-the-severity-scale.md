# 397 — The reviewer agent names the severity scale

- **Status:** accepted — adopted-as-recommended (no user judgment)
- **Date:** 2026-10-07
- **Design:** docs/contributing/design/eval-sweep-followups.md · **Supersedes/Refines:** none

## Context

The scale CRITICAL|HIGH|MEDIUM|LOW lives only in `contracts/harness-read.md`, which only the review phase injects. Spawned directly, the reviewer wrote the scale in 1 of 3 opus runs and 0 of 3 sonnet and haiku runs; that cost 8 of the 9 structured-review points the sweep lost. Putting the scale in the agent duplicates it, so the two copies need a guard.

## Options considered

1. **One Contract bullet naming the set `{CRITICAL, HIGH, MEDIUM, LOW}`, plus a test that the agent's severity and claim-status sets equal the contract's** *(recommended)* — pros: smallest duplication, drift caught by CI / cons: the scale is stated twice in the review phase
2. **Copy the whole finding shape from the contract into the agent** — pros: one source of shape outside the phase / cons: duplicates `file:line`, which a missing-test finding cannot cite
3. **Point the agent at the contract by path** — pros: no duplication / cons: a directly spawned agent and the six mirrors have no plugin-root path

## Decision

Adopted as recommended (option 1). The reviewer agent states the severity set; the per-line shape stays in the contract. A structure test pins the agent's severity and status sets to the contract's. The six adapter mirrors are regenerated by `scripts/sync-adapter-agents.sh`.

## Consequences

- Changing the scale means editing the contract and the agent together, or CI fails.
- The `findings-shape` grader is unchanged.
