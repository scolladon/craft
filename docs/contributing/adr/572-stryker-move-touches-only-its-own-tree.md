# 572 — The Stryker move changes only the Stryker tree in the lockfile

- **Status:** accepted
- **Date:** 2026-10-14
- **Design:** docs/contributing/design/stryker-9-upgrade.md · **Supersedes/Refines:** none

## Context

Before the move, `npm --prefix engine audit` reports 16 advisories: 15 from the Stryker tree and one
from the runtime dependency `js-yaml`. Installing 10.0.0 leaves 3: `qs` and `typed-rest-client`
(moderate, inside the Stryker tree) and `js-yaml` (high). `npm audit fix` on top reaches 0, but it moves
the runtime `js-yaml` and downgrades `typed-rest-client` to 2.3.0.

Review then showed that the 3 left are not all old. Core 10.0.0 asks for `typed-rest-client ~2.3.0`;
npm picks 2.3.1, which pins `qs` exactly at 6.15.1. Before the move the tree held `qs@6.15.2`, so the
install downgrades `qs` and adds GHSA-q8mj-m7cp-5q26 (`qs.stringify` DoS, `>=6.11.1 <=6.15.1`) to the
two `qs` advisories already present. `typed-rest-client@2.3.0`, also inside core's range, accepts
`qs ^6.14.1`, and `qs@6.16.0` clears all three.

## Options considered

1. **Install the two packages only** — pros: the lockfile diff is the Stryker install alone / cons:
   the install itself adds a `qs` advisory. *(designer's recommendation, adopted first)*
2. **Also run `npm audit fix`** — pros: 0 advisories / cons: changes a production dependency
   inside a tooling change.
3. **Install the two packages, override `typed-rest-client` to 2.3.0 and update `qs`** — pros:
   Stryker-tree advisories drop to 0, the runtime tree is untouched, 2.3.0 is inside core's own range /
   cons: one `overrides` entry to drop once core resolves past the exact `qs` pin.

## Decision

Option 3, ratified by the user after review surfaced the `qs` downgrade (option 1 had been adopted as
recommended, with no user judgment, on the premise that the install only removes advisories).
`engine/package.json` carries `"overrides": { "typed-rest-client": "2.3.0" }`; the lockfile is
regenerated by npm only: `npm install --save-dev --save-exact` of the two packages, `npm install`
after the override, and `npm update qs`. It is never hand-edited, and `npm audit fix` is not run.

## Consequences

- Stryker-tree advisories drop from 15 to 0; the `js-yaml` advisory is untouched.
- A change to a runtime dependency stays its own reviewed change.
- The override is dropped when a Stryker release resolves `typed-rest-client` to a version whose
  `qs` range admits a fixed `qs`.
