# 572 — The Stryker move changes only the Stryker tree in the lockfile

- **Status:** accepted
- **Date:** 2026-10-14
- **Design:** docs/contributing/design/stryker-9-upgrade.md · **Supersedes/Refines:** none

## Context

Today `npm --prefix engine audit` reports 16 advisories: 15 from the Stryker tree and one from the
runtime dependency `js-yaml`. Installing 10.0.0 leaves 3: `qs` and `typed-rest-client` (moderate,
inside the Stryker tree) and `js-yaml` (high). `npm audit fix` on top reaches 0, but it moves the
runtime `js-yaml` and downgrades `typed-rest-client` to 2.3.0.

## Options considered

1. **Install the two packages only** — pros: the lockfile diff is the Stryker tree alone / cons:
   2 Stryker-tree advisories and the `js-yaml` one remain. *(designer's recommendation)*
2. **Also run `npm audit fix`** — pros: 0 advisories / cons: changes a production dependency
   inside a tooling change.
3. **Install plus a targeted `npm update qs`** — pros: might clear `qs` / cons: not probed; the
   `qs` range `typed-rest-client@2.3.1` accepts may make it a no-op.

## Decision

Adopted-as-recommended (no user judgment): option 1. The lockfile is regenerated by
`npm install --save-dev --save-exact` of the two packages and nothing else; it is never
hand-edited.

## Consequences

- Stryker-tree advisories drop from 15 to 2; the `js-yaml` advisory is untouched.
- A change to a runtime dependency stays its own reviewed change.
