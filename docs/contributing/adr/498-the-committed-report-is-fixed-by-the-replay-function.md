# 498 — The committed report is fixed by the replay function

- **Status:** accepted
- **Date:** 2026-10-12
- **Design:** docs/contributing/design/baseline-review-waste-replay-guard.md · **Supersedes/Refines:** none

## Context

The committed report must agree with the guard. A hand-edit could disagree with the function the guard runs; a committed `--write` bin adds surface for a one-off.

## Options considered

1. **Throwaway one-off running `replayRecommendations` then `serializeReport`, documented in the telemetry spec** *(recommended)* — pros: the guard and the fix share one source
2. **A committed `--write` bin** — pros: repeatable / cons: new surface for a rare operation
3. **Hand-edit** — pros: no code / cons: can disagree with the guard

## Decision

Option 1 — **adopted-as-recommended (no user judgment).** The committed report is regenerated by `replayRecommendations` plus `serializeReport`; the command is documented in `docs/contributing/specs/telemetry.md`. Aligns with KISS/YAGNI.

## Consequences

The diff is confined to `recommendations`; `runs` stays byte-identical.
