# 444 — The handback gives an out-of-part GUARD a blocker, not a RED/GREEN line

- **Status:** accepted — adopted-as-recommended (no user judgment)
- **Date:** 2026-10-10
- **Design:** docs/contributing/design/arriving-guard-part-bound.md · **Supersedes/Refines:** refines ADR-435

## Context

The part-implementer's Final-message bullet gives every `GUARD` that failed on its first run a RED/GREEN line and the `PLAN-MISMATCH` observation. Under ADR-443 a `GUARD` whose GREEN lies outside the part has no GREEN, so the bullet and the contract would disagree in the same spawn. Haiku follows the bullet: contract prose alone left its mismatch report at 0 of 3, the bullet's token moved it to 3 of 3, and one haiku run that edited the other part's file reported in the bullet's RED/GREEN shape.

## Options considered

1. **Leave the bullet unchanged** — pros: the after-measure isolates the contract's effect / cons: two texts disagree on the out-of-part case
2. **Bound the RED/GREEN line to a GREEN inside the part** — pros: removes the contradiction / cons: the out-of-part outcome rests on the contract text haiku overrode
3. **Option 2, plus: one whose GREEN lies outside the part gets no RED/GREEN line; hand back a blocker whose reason carries that `PLAN-MISMATCH` line** *(recommended)* — pros: names, where haiku reads, the blocker every blocked run already returned / cons: +167 characters per spawn; six adapter mirrors regenerate; the after-measure cannot separate contract from bullet

## Decision

Adopted-as-recommended (no user judgment): option 3, following the reasoning of ADR-434.

## Consequences

- The adapter mirrors are regenerated by `scripts/sync-adapter-agents.sh --write`, never hand-edited.
