# Plan — haiku-arriving-guard-handback

> Source: design doc `docs/contributing/design/haiku-arriving-guard-handback.md` · ADRs 434, 435, 436
> The plan is the implementation script AND the knowledge handoff. Part agents start
> with zero context: whatever a part block omits is paid later as agent rediscovery.
> `plan-lint.sh` enforces the schema below — the plan phase cannot close without it.

## Sizing rules

- Every part costs a full agent lifecycle (spin-up, zero-context rebuild, gate) — it
  must earn it. No standalone test-only parts for FEATURE code: coverage/interop/property
  tests fold into the implementation part whose code they exercise. EXCEPTION:
  test-infra-only and docs-only parts (tooling config, test helpers, fixtures,
  harness/ADV/property suites, docs/prose) with no `src/` delta ARE standalone — they
  have no implementation part to fold into.
- A part that would be a pure test pass over already-landed code merges into its
  neighbour.
- A part should land in ~100 tool calls. More than ~5 RED→GREEN cycles, or more than 6
  files in its `### Context` block, is two parts. What counts is a backticked path:
  backtick the files the part CREATES or EDITS, and write read-only reference paths in
  plain text.

**How this plan applies them.** One part, one RED→GREEN cycle. The pin test exists only to
guard the line the GREEN writes, so it folds into the same part. Two files are edited by hand
(the agent body and the test file); six adapter mirrors are regenerated by a script and land
in the same commit. Revertible on its own.

- **README corpus count.** The plan commit bumps README.md l. 180 from "[38 parted plans]" to
  "[39 parted plans]" (test/readme-drift.test.js checks it against the live tree). The part
  adds no design doc, plan or ADR, so it does not touch README.md. The ADR count already reads
  "[436 ADRs]" and stays.
- **Pre-probed.** Before this plan was written, a throwaway `git clone` of this branch (HEAD
  5aa614b, with the worktree's engine/node_modules symlinked in) took every step below:
  - pin test inserted after the reviewer claim-status test: `node --test
    test/p10-structure.test.js` gave `# pass 23`, `# fail 1`, the one failure being the new
    test (`not ok 23`);
  - line 16 replaced, then `bash scripts/sync-adapter-agents.sh --write`: six lines
    "`<adapter>/part-implementer: rewritten`" then "54 mirrors in sync across 6 adapters.";
    `--check` printed the same summary and exited 0;
  - `node --test test/p10-structure.test.js`: `# pass 24`, `# fail 0`;
  - `git diff --no-ext-diff --stat`: 8 files (the agent body, the six mirrors, the test
    file), each mirror and the agent body `1 +-`;
  - committed in the clone, `bash scripts/ci.sh` exit 0 (about 32 000 lines of output), last
    line "sync-adapter-agents: 54 mirrors in sync across 6 adapters.".

**Public surface.** No new exported symbol. The new `PART_IMPLEMENTER_AGENT` const is local to
test/p10-structure.test.js (internal). The agent body is a plugin surface, but its only
downstream surface gate is the adapter mirror set, which the part regenerates in-part and
`sync-adapter-agents.sh --check` (inside `scripts/static-lints.sh`, called by `ci.sh`) checks.
No skill, contract, guide, README line or registry quotes the bullet's text (design P2).

**Binding for the part.**

- No provenance references (ADR numbers, design ids, phase or backlog ids) in the agent body or
  the test. No suppression directives. No swallowed errors.
- Do not hand-edit the six mirrors; do not touch `contracts/construction.md`,
  `engine/test/contract-equivalence.test.js`, `evals/implementer-runs-guards/**`,
  `agents/planner.md` or `templates/plan.md`.
- Commit only the eight files (`git add <each path>` then `git commit -m "<message>"`); never
  touch the branch, the stash, or other files; never checkout/restore/reset to undo.
- `bash scripts/ci.sh` prints about 32 000 lines: write it to a `mktemp` file and read back
  with `tail`/`grep`.

`GUARD` slot, ADR-436 prefix pin). The plan adds one execution-level choice.

## Part 1 — name an arriving GUARD with a PLAN-MISMATCH token in the part-implementer handback

### Context

Files this part edits by hand:

- `agents/part-implementer.md` — 16 lines. Frontmatter lines 1–6 (`model: sonnet`), stays
  byte-identical. Line 14 `Contract:`, line 15 blank, line 16 is the only bullet and the only
  line that changes. Current line 16, verbatim:

  ```
  - Final message: the commit hash + one line per RED/GREEN cycle and per `GUARD`, plus any deferred observations.
  ```

  Replacement line 16, verbatim (one line, ends with a period, no trailing space):

  ```
  - Final message: the commit hash + one line per RED/GREEN cycle and per `GUARD` that passed on its first run, plus any deferred observations. A `GUARD` that failed on its first run gets a RED/GREEN line and the deferred observation `PLAN-MISMATCH(<test title>): the plan expected it to pass; it failed on its first run`.
  ```

  Use the Edit tool with the exact old and new strings: the line holds backticks, so a `sed`
  one-liner is fragile.

- `test/p10-structure.test.js` — 364 lines, `node:test` + `node:assert`; `fs`, `path` and
  `ROOT` (`path.join(__dirname, '..')`, line 8) are already in scope. The reviewer-agent
  block starts at line 296 (`const REVIEWER_AGENT = …`, `const HARNESS_READ_CONTRACT = …`),
  followed by `agentSetFor`, `contractSetFor` and two tests; the claim-status test closes
  with `);` on line 340. Insert the new const and test right after line 340, before the test
  "Given every agent, when its tools list is read, then no entry is an MCP tool or a
  sub-agent-spawning tool". Exact text (the pre-probe ran the same assertion with the
  `assert.ok` call on one line; this plan wraps it to the file's style):

  ```js

  const PART_IMPLEMENTER_AGENT = path.join(ROOT, 'agents/part-implementer.md');

  test(
    'Given the part-implementer agent, when its body is read, then it names the PLAN-MISMATCH token for a GUARD that failed on its first run',
    () => {
      const sut = fs.readFileSync(PART_IMPLEMENTER_AGENT, 'utf8');

      const result = sut.includes('PLAN-MISMATCH(<test title>):');

      assert.ok(
        result,
        'agents/part-implementer.md should name the PLAN-MISMATCH(<test title>): token',
      );
    },
  );
  ```

  Do not use the file's `grepQ` helper: it runs `grep -qx` (whole-line match).

Files regenerated by script, never hand-edited (same commit):
`adapters/{aider,antigravity,codex,copilot,cursor,opencode}/agents/craft-part-implementer.md`.
Run `bash scripts/sync-adapter-agents.sh --write` after the agent edit. It rewrites each
mirror's body and keeps its frontmatter byte-for-byte. Expected output: six
"sync-adapter-agents: <adapter>/part-implementer: rewritten" lines, then "sync-adapter-agents:
54 mirrors in sync across 6 adapters.".

Read-only references (plain text, do not edit): contracts/construction.md line 1 (the
arriving-GUARD rule whose words the new line reuses), scripts/sync-adapter-agents.sh,
scripts/static-lints.sh (runs `sync-adapter-agents.sh --check`), test/readme-drift.test.js.

### TDD steps

1. **RED** — add the `PART_IMPLEMENTER_AGENT` const and the test above to
   test/p10-structure.test.js. Run `node --test test/p10-structure.test.js 2>&1 | grep -E
   "^# (pass|fail)|^not ok"`. Expected: `# pass 23`, `# fail 1`, `not ok 23 - Given the
   part-implementer agent, …`. It fails because line 16 of agents/part-implementer.md names no
   `PLAN-MISMATCH(` token, so `sut.includes(…)` returns `false`.
2. **GREEN** — replace line 16 of agents/part-implementer.md with the replacement line above
   (only that line). Run `bash scripts/sync-adapter-agents.sh --write`, then
   `bash scripts/sync-adapter-agents.sh --check` (exit 0, "54 mirrors in sync across 6
   adapters."). Re-run the test file: `# pass 24`, `# fail 0`.
3. **REFACTOR** — none expected. Check `git diff --no-ext-diff --stat`: exactly the eight files
   (agent body and six mirrors `1 +-` each, test file 16 insertions), and
   `git diff --no-ext-diff agents/part-implementer.md` shows only line 16 changed.

### Gate

```bash
LOG=$(mktemp); bash scripts/ci.sh > "$LOG" 2>&1; echo "exit=$?"; tail -5 "$LOG"
```

Must print `exit=0`. It runs the root `test/` suite (with the new pin), the engine suite
(`contract-equivalence.test.js` unchanged), `static-lints.sh` (incl.
`sync-adapter-agents.sh --check`, design-lint) and readme-drift. No shell file is touched, so
shellcheck is not part of this gate. On a non-zero exit, `grep -nE "not ok|FAIL|Error" "$LOG" |
head` locates the failure; never commit on red.
