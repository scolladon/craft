# Plan — activate-dod-and-live-doc-lints

> Source: design doc `docs/design/activate-dod-and-live-doc-lints.md` · ADRs `178, 179, 180, 181`
> The plan is the implementation script AND the knowledge handoff. Part agents start
> with zero context: whatever a part block omits is paid later as agent rediscovery.
> `plan-lint.sh` enforces the schema below — the plan phase cannot close without it.

## Sizing rules

- Every part costs a full agent lifecycle (spin-up, zero-context rebuild, gate) — it
  must earn it. No standalone test-only parts for FEATURE code: coverage/interop/property
  tests fold into the implementation part whose code they exercise. EXCEPTION:
  test-infra-only and docs-only parts (tooling config, test helpers, fixtures,
  harness/ADV/property suites, docs/prose) with no `src/` delta ARE standalone — they
  have no implementation part to fold into.
- A part that would be a pure test pass over already-landed code merges into its
  neighbour.

> **Partition (user mandate): EXACTLY TWO PARTS, each its own atomic conventional commit.**
> Part 1 (T1) and Part 2 (T2) share no source file, so order is free; they land sequentially
> on one working tree (`feat/activate-dod-and-live-doc-lints`). Each part ships behavior +
> its own tests (neither is test-only). Do NOT sub-split a part into multiple commits.

> **Cumulative-counter rule (applies to BOTH parts — the LAST step before each commit).**
> `EXPECTED_TESTS` (`scripts/ci.sh:10`, asserted TWICE — engine-cwd run and repo-root run,
> both must equal the one variable) and `EXPECTED_PROC_TESTS` (`scripts/ci.sh:44`) are GLOBAL
> totals asserted inside `ci.sh`. They are NOT deltas. As the final pre-commit step, run
> `bash scripts/ci.sh`, read the actually-emitted `# tests <N>` line from each run, and set
> `EXPECTED_TESTS` + `EXPECTED_PROC_TESTS` to those exact emitted totals — do NOT trust the
> estimates in this plan or the design. A part is green only when its tests pass AND the
> counters equal the emitted counts. `EXPECTED_PI_TESTS=202` is untouched by both parts.
> The design's per-part estimates (Part 1: `EXPECTED_TESTS` ~1234→~1239, `EXPECTED_PROC_TESTS`
> ~117→~127; Part 2: `EXPECTED_PROC_TESTS` ~127→~130, `EXPECTED_TESTS` unchanged) are
> ESTIMATES only.

## Part 1 — activate the structured-DoD auto-assertion (T1)

### Context

**Goal.** A declared `kind: auto` DoD criterion is mechanically asserted from the run's
recorded per-phase gate evidence; `kind: judgment` stays human-asserted; the non-blocking
`NO-OP(verify)` no-DoD path is unchanged; a red/absent gate can NEVER be read as green
(ADR-174 + ADR-178). This wires the DORMANT DC-5 v2 sidecar (`engine/src/dod.js`) into a
runtime call path: a pure gate-evidence builder, a new CQS-reporter bin, a fixed per-phase
gate token emitted by the run skill, and a mechanical call in the validation skill.

**Files to touch (exact paths + current state).**

- `engine/src/dod.js` (PURE — header *"Pure — no I/O. All file reads and gate evidence are
  injected."*; HONOUR it). Current exports: `parseDod(content) → { criteria } | null` (THROWS
  on malformed frontmatter), `validateDodCriteria(criteria) → string[]`,
  `assertDodCriteria(criteria, evidence) → ('met'|'unmet'|'judgment')[]`. Private
  `assertAutoCriterion(crit, evidence)` consumes
  `evidence = { gateGreen: (phaseId) => boolean|undefined, fileExists: (path) => boolean }`
  and returns `'met'` for a `gate` criterion **iff** `evidence.gateGreen(assert.gate) === true`,
  else `'unmet'` (the `=== true` is load-bearing: `false`/`undefined` → `'unmet'`). ADD ONE new
  pure export:
  ```js
  export function buildGateGreen(greenPhaseIds) {
    const green = new Set(greenPhaseIds);
    return (phaseId) => green.has(phaseId); // boolean: red/absent ⇒ false ⇒ '=== true' fails ⇒ 'unmet'
  }
  ```
  Keep ALL existing exports. `Set.has` returns a strict `boolean`, so a red/absent id → `false`,
  which `assertAutoCriterion`'s `=== true` rejects → `'unmet'` (fail-closed, the ADR-174 crux).
- `engine/src/contain.js` (PURE-ish — fs realpath). Exports `containByRealpath(root, target) →
  string|null` (fail-closed `null` on lexical escape, symlink leaf incl. dangling, realpath
  ancestor escape, or any non-ENOENT fs error) and `realExistingPrefix(absPath)`. This is the
  containment primitive the bin's `file-exists` evidence MUST use. Do NOT edit this file.
- `engine/src/frontmatter.js` — `extractFrontmatter(content) → string|null` (null when no/empty
  `---` block). Already consumed by `parseDod`; no edit. Knowing it: a free-text DoD (no fence)
  → `parseDod` returns `null` (the non-blocking path); a fence that opens but is bad YAML →
  `parseDod` THROWS (fail-loud).
- `engine/bin/dod-assert.js` — **NEW bin.** Per the design (ADR-180 reporter) and the verified
  bin convention, this bin HOLDS `main(argv, io)` INLINE — it is NOT split into a separate
  `engine/src/dod-assert-main.js`. Rationale: every decision is already pure-core
  (`dod.js` + `contain.js`), and the bin is OUTSIDE Stryker's mutate scope
  (`engine/src/**/*.js` only — verified in `engine/stryker.conf.json`), so its glue carries no
  mutants to strand. Mirror the I/O shape of `engine/src/init-land-main.js`'s `main`:
  `main(argv, io)` returns a numeric exit code; writes go through `io.stdout.write(...)` /
  `io.stderr.write(...)`; constants `EXIT_OK = 0`, `EXIT_ERR = 1`. The bottom-of-file run guard
  mirrors `engine/bin/init-land.js`:
  ```js
  if (process.argv[1] === fileURLToPath(import.meta.url)) {
    process.exit(main(process.argv.slice(2), { stdout: process.stdout, stderr: process.stderr }));
  }
  ```
  Imports: `{ parseDod, validateDodCriteria, assertDodCriteria, buildGateGreen }` from
  `../src/dod.js`; `{ containByRealpath }` from `../src/contain.js`; `{ existsSync, readFileSync }`
  from `node:fs`; `{ resolve }` from `node:path`; `{ fileURLToPath }` from `node:url`.
  - **argv contract:** `argv[0]` = DoD file path; `argv[1]` = **repo root**; `argv[2]` =
    comma-separated green phase-ids (optional; empty/absent ⇒ no green gates recorded). The
    repo root is passed EXPLICITLY (not derived from `import.meta.url`) because the bin lives in
    `${CLAUDE_PLUGIN_ROOT}/engine/bin/` whereas the validated repo is the USER's repo — a
    DIFFERENT root; `file-exists` containment must bind to the user's repo, never the plugin root.
  - **Local glue helper** (lives in the bin, NOT in `dod.js` — needs fs + containment):
    ```js
    function buildFileExists(repoRoot, deps) {
      return (relOrAbs) => {
        const contained = containByRealpath(repoRoot, resolve(repoRoot, relOrAbs));
        return contained !== null && deps.exists(contained); // null ⇒ escaped ⇒ false ⇒ 'unmet'
      };
    }
    ```
  - **`main` flow:** missing `argv[0]`/`argv[1]` → usage line to `io.stderr`, return `EXIT_ERR`.
    `readFileSync(dodPath)` (catch read error → message to `io.stderr`, return `EXIT_ERR`).
    `parseDod(content)` wrapped in try/catch — a THROW (malformed frontmatter) → write the
    message to `io.stderr`, return `EXIT_ERR` (fail loud). `null` (free-text / no `criteria`) →
    `io.stdout.write(JSON.stringify({ outcomes: null }) + '\n')`, return `EXIT_OK` (non-blocking
    no-DoD path). Else `validateDodCriteria(parsed.criteria)`; non-empty errors → write each to
    `io.stderr`, return `EXIT_ERR`. Build `evidence = { gateGreen: buildGateGreen(greenIds),
    fileExists: buildFileExists(repoRoot, { exists: existsSync }) }` where
    `greenIds = (argv[2] ?? '').split(',').map(s => s.trim()).filter(Boolean)`. Call
    `assertDodCriteria(parsed.criteria, evidence)`; zip into
    `outcomes = parsed.criteria.map((c, i) => ({ id: c.id, kind: c.kind, outcome: results[i] }))`;
    `io.stdout.write(JSON.stringify({ outcomes }) + '\n')`; return `EXIT_OK`. The single
    `{ "outcomes": … }` envelope (array when structured, `null` when free-text) gives the SKILL
    one stable parse shape. The bin NEVER executes a DoD-supplied `command`/`run` field —
    `assertDodCriteria` already ignores them.
- `skills/run/SKILL.md` — Phase-walk **step 6 (Gate)** / **step 7 (Record outcome)** (lines
  ~240-255). At each phase-boundary gate, EMIT the fixed greppable token
  `GATE(<phase-id>): green` or `GATE(<phase-id>): red` into the in-session run record — a fixed
  `TOKEN(<param>):`, distinct from `WAIVER:`, `NO-OP(<phase>):`, and `auto-skip: <phase> …`.
  An auto-skipped/waived executing-harness records NO `GATE(...)` line (its phase produced no
  recorded gate result), so its id is simply absent from the green set ⇒ any criterion naming it
  ⇒ `'unmet'` (fail-closed). GENERIC vocabulary only (`skills/` is source-hygiene-scanned — NO
  technique names, NO `gh`/`github`).
- `skills/validation/SKILL.md` — Preamble step 2, the **"Structured sidecar"** bullet (lines
  ~35-45) which today describes the intent in PROSE and performs no call. Change it to a
  MECHANICAL call: collect the green phase-ids from the run record's `GATE(<phase-id>): green`
  lines, then invoke
  `node "${CLAUDE_PLUGIN_ROOT}/engine/bin/dod-assert.js" <dod-path> <repo-root> <green-ids-csv>`
  via Bash, parse the `{ "outcomes": … }` JSON, record each `{ id, kind, outcome }`, escalate any
  `auto` `'unmet'` as the existing blocker `{ verify, "<criterion> unmet", ≤3 options }`
  (headless → record + halt, never a silent pass), keep `judgment` human-asserted, and keep the
  `{ "outcomes": null }` free-text branch on the existing `NO-OP(verify): no DoD declared` line.
  PRESERVE the literal `NO-OP(verify):` token (guarded by `test/no-op-token.test.js`) and the
  Absent/Present free-text semantics; only the Structured-sidecar sub-branch becomes mechanical.
  GENERIC vocabulary only (this file is source-hygiene-scanned).
