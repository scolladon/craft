## Sizing rules

- Every part costs a full agent lifecycle (spin-up, zero-context rebuild, gate) — it
  must earn it. No standalone test-only parts for FEATURE code: coverage/interop/property
  tests fold into the implementation part whose code they exercise. EXCEPTION:
  test-infra-only and docs-only parts (tooling config, test helpers, fixtures,
  harness/ADV/property suites, docs/prose) with no `src/` delta ARE standalone — they
  have no implementation part to fold into.
- A part that would be a pure test pass over already-landed code merges into its
  neighbour.
- A part should land in ~100 tool calls. More than ~5 RED→GREEN cycles, or more than 6
  files in its `### Context` block, is two parts. What counts is a backticked path:
  backtick the files the part CREATES or EDITS, and write read-only reference paths in
  plain text.

### Context

12 `describe` blocks, the last `'createAppServerRunner() — double-settle pin'` at L358-373). It imports

The survivor: adapters/codex/src/app-server-client.js:87, `clearTimeout(timer);` inside `finish`
(L84-90) in `runAppServer` (the function `createAppServerRunner({ spawn })` returns, L71-142; spawn at
L76, the `timer = setTimeout(…, timeoutMs)` at L92-96, `timeoutMs` defaults to
`DEFAULT_TIMEOUT_MS = 10_000`, L15). Class "timer / process teardown". Removing the call leaves the
10 s timer pending after a successful settle; when it fires, `finish`'s `settled` guard (L85) makes it
a no-op, so no promise result can see it. The only observable is the pending handle.

Kill approach (decision candidate 1, option a): count `'Timeout'` entries in
`process.getActiveResourcesInfo()` before the call and after the awaited success. The fake child emits
`data` synchronously, so `finish` runs before `await` yields and the await resumes in a microtask: no
timer (node:test's or a leftover from an earlier test) can fire inside the measured window, which
makes the delta deterministic.

Where to add: a new `describe` block appended after the double-settle block (after L373). The block
(pinned, probed):

```js
describe('createAppServerRunner() — the timeout timer is released on settle', () => {
  it('Given a run whose response arrives before the timeout, when the runner resolves, then it leaves no pending timer behind', async () => {
    const { child } = createFakeChildProcess();
    const { spawn } = createFakeSpawn(child);
    const sut = createAppServerRunner({ spawn });
    const countPendingTimers = () => process.getActiveResourcesInfo().filter((resource) => resource === 'Timeout').length;
    const pendingBefore = countPendingTimers();

    const runPromise = sut({ requests: [], cwd: CWD, env: ENV, responseId: RESPONSE_ID });
    child.stdout.emit('data', responseLine(RESPONSE_ID));
    await runPromise;

    assert.equal(countPendingTimers(), pendingBefore);
  });
});
```

Do NOT pass a `timeoutMs`: the default 10 s timer is the one the source leaves pending, and a short
one could fire before the assertion. No fallback comment lands in the source: the kill exists.

### TDD steps
