# Design — stryker-9-upgrade

> Brief: Stryker is pinned to 8.7.1 for a Node floor the engine no longer declares. ADR-047 DC-2a chose
> `@stryker-mutator/core@8.7.1` because 9.x requires Node `>=20` and the engine declared `>=18`. The engine
> now declares `^22.18.0 || >=24.2.0` (ADR-564). Move off 8.7.1 with its own ADR against ADR-047 and a full
> mutation run that compares scores and timings with 8.7.1.
> Status: draft → self-reviewed ×3 → revised against ADR-570 (target 10.0.0, ratified), ADR-571 (exact
> pins) and ADR-572 (install-only lockfile) → self-reviewed ×3

## Requirements

- R1: `engine/package.json` pins `@stryker-mutator/core` and `@stryker-mutator/tap-runner` to the exact

  install and nothing else (ADR-572). `cd engine && npm ci` exits 0 on Node 22.
- R2: every key in `engine/stryker.conf.json` still validates against the 10.0.0 option schemas, with
  the same meaning. The file stays byte-identical, because the schema check forces no change.
- R3: a full `npm --prefix engine run mutation` on 10.0.0 passes the acceptance comparison against the
  8.7.1 baseline (A1-A6, Test strategy). Mutation stays out of `ci.sh` (DC-2c).
- R4: on the engine's supported 24 line, the runner receives TAP from every test file. This is a defect
  of 8.7.1, pinned below.
- R5: ADR-570 records the move against ADR-047 DC-2a/2b; it is already committed.
  `node engine/bin/adr-lint.js docs/contributing/adr` exits 0 on the final tree.
- R6: the BACKLOG item is closed in the house form (title suffixed "— delivered", original entry kept).
  The closed text carries no `ADR-047` token (C3).
- R7: `npm --prefix engine audit` reports 2 advisories from the Stryker tree, down from today's 15,
  measured on the committed lockfile.
- R8: `bash scripts/ci.sh` is green.
- R9: every `CallExpression` mutant that 10.0.0 adds (171, listed below) ends Killed or Timeout, or
  is dispositioned as equivalent per candidate 5. A survivor is killed by a behavioural test added to a
  suite the run already collects: an `engine/test/**/*.test.js` file, or an adapter file already listed in
  `tap.testFiles`. A new adapter test file would need a `tap.testFiles` entry and would break R2. An
  equivalent mutant that stays in the code is documented in the house form,
  `// equivalent mutant (CallExpression ;): <argument>`, next to the statement (inline or on the line
  above, as the existing comments are; `.claude/workflow.md` L36; DOD `techniques-triaged`).

## Design

### Pinned: what changes between 8.7.1, 9.6.1 and 10.0.0

Method: throwaway copies of `engine/package.json` + `engine/package-lock.json` in `mktemp -d`,
`npm install --save-dev --save-exact --ignore-scripts @stryker-mutator/core@<v> @stryker-mutator/tap-runner@<v>`,
on Node 22.22.3 with npm 12.2.0. Changelogs come from `packages/{core,instrumenter,tap-runner}/CHANGELOG.md`
of `stryker-mutator/stryker-js`, fetched with `gh api`. The mutant sets come from each version's own
`Instrumenter.instrument()` run over the 97 `mutate` files, with `excludedMutations: []`. Every mutant is
keyed by file, start/end line:column, mutator and replacement, and the sorted lists are compared.

| | 8.7.1 (today) | 9.6.1 | 10.0.0 |
|---|---|---|---|
| core `engines.node` | `>=18.0.0` | `>=20.0.0` | `>=22.0.0` |
| tap-runner `engines.node` / peer | `>=14.18.0` / `core: ~8.7.0` | `>=14.18.0` / `core: 9.6.1` (exact) | `>=22.0.0` / `core: 10.0.0` (exact) |
| Breaking changes (CHANGELOG) | — | 9.0.0: drop Node 18; vitest-runner ≥ v2 (not used) | 10.0.0: drop Node 20 |
| tap-runner `dist/` vs previous column | — | default `tap.nodeArgs` gains `--test-reporter=tap`; core `testFiles` honoured in dry run; the rest is formatting | byte-identical to 9.6.1 apart from `package.json` |
| core option schema (`api/dist/schema/stryker-core.json`) vs previous | — | added top-level `testFiles` (default `[]`); `concurrency` also accepts `"50%"`; no key removed, no default changed | one description string changed |
| Mutants over our 97 files | 10141 | **10141, byte-identical set** | 10312 = the same 10141 + **171 `CallExpression`** |
| `npm audit` (whole engine tree) | 16: 5 low, 4 moderate, 7 high | 3: `qs` moderate, `typed-rest-client` moderate, `js-yaml` high | same 3 |
| …of which from the Stryker tree | 15 | 2 (`qs` via `typed-rest-client@2.3.1`) | 2 (same) |
| Locked packages | 210 | 175 | 178 |
| Lockfile diff vs today | — | +568 / −933 | +850 / −1145 |

The 171 new mutants in 10.0.0 come from the new `empty-expression-mutator` (instrumenter 10.0.0,
stryker-js #6012). It is enabled by default and replaces a call statement with `;`, for example
`clearTimeout(timer);` or `child.kill();`. Its filter keeps a mutant only when it is alone in scope. All
171 are statement removals, none is a `throw`. With `mutator.excludedMutations: ["CallExpression"]`,
10.0.0 still emits 577 `CallExpression` mutants, marked Ignored, because the filter skips mutants that
carry an ignore reason. Excluding the mutator therefore does not restore a clean count. ADR-570 keeps the
mutator on and puts all 171 in scope (R9).

The js-yaml advisory is the engine's runtime dependency and is out of scope. `npm audit fix` on top of the
9.6.1 install (the 10.0.0 tree has the same 3 advisories) reaches 0 advisories, but it does that by moving `js-yaml` (`4.3.2`) and downgrading
`typed-rest-client` to 2.3.0 (`qs@6.16.0`). ADR-572 rejects that and keeps the install-only lockfile.

### Pinned: what the runner receives, per Node

The tap-runner spawns `node <tap.nodeArgs> <testFile>` (`tap-test-runner.js` `runFile`) with a CJS preload
`-r <tap-runner>/dist/src/setup/hook.cjs`. Each version's default `nodeArgs` (8.7.1:
`-r {{hookFile}} {{testFile}}`; 9.6.1/10.0.0: `--test-reporter=tap -r {{hookFile}} {{testFile}}`) was run
against a one-test `node:test` file in a `mktemp -d`, with stdout redirected (non-TTY,
`STRYKER_DRY_RUN=true`). The test spawns a child Node and asserts that the child's stderr is `''`.

| Node | 8.7.1 args | 9.6.1 args | 10.0.0 args |
|---|---|---|---|
| 22.22.3 | TAP (`TAP version 13`, `ok 1`), stderr 0 B | TAP, stderr 0 B | TAP, stderr 0 B |
| 24.11.0 | **spec reporter** (`✔ …`), 0 TAP lines, stderr 0 B | TAP, stderr 0 B | TAP, stderr 0 B |
| 25.1.0 | **spec reporter**, 0 TAP lines, stderr 0 B | TAP, stderr 0 B | TAP, stderr 0 B |

8.7.1's own `TapParser` was fed the spec output of a passing file. It returns
`{ ok: true, count: 0, plan.skipReason: "no tests found" }`. A failing file exits 1 with no TAP `not ok`
line, so it reaches `captureTapResult`'s "Tap process exited with code" throw
(`@stryker-mutator/tap-runner@8.7.1` `dist/src/tap-helper.js` L33-35). So on Node 24.11.0 and 25.1.0,
8.7.1 cannot score a run with today's config (R4). How Stryker classifies those mutants end to end was not
probed. A narrowed 8.7.1 run on 24.11.0 would show it, and the move does not depend on the answer. The
9.0.0 tap-runner changelog entry "provide `--test-reporter=tap` as default nodeArg" is the fix.

**Loader hooks and stderr.**

- No `module.register`, `--import`, `--loader` or `--experimental-loader` appears in the `dist/` of core,
  api, util or tap-runner for any of the three versions. Node 26's DEP0205 (`module.register`) therefore
  cannot fire from Stryker. Node 26 is not installed on this box, so that rests on the grep, not a run.
- The repo's only loader hook is `engine/test-helpers/swap-link-on-load.js` L8/L27, which uses
  `registerHooks` (not DEP0205). It is passed with `--import` by `engine/test/bin-entry-swap-race.bin.test.js`
  L50 and `adapters/codex/test/trust-hook.bin.test.js` L62.
- The runner passes its preload through argv, not `NODE_OPTIONS`, so children spawned by tests do not
  inherit it. They do inherit the `STRYKER_*` env, as on 8.7.1.
- Exact empty-stderr assertions on a spawned child exist only at `adapters/codex/test/trust-hook.bin.test.js`
  L107 and `adapters/pi/test/cli.test.js` L233 (`craft-guard-hook.test.js` L132 asserts non-empty). None of
  these files is in `tap.testFiles`. No file in the Stryker
  corpus asserts that a spawned child's stderr is `''`. The in-process `io.stderr.joined()` assertions use
  fakes, which the runner does not touch.

## Test strategy

**Gate.** `bash scripts/ci.sh` green (R8). It includes `design-lint`, `adr-lint` (R5, R6) and every
`node --test` suite. `cd engine && npm ci` exits 0 on Node 22 against the regenerated lockfile (R1).
`npm --prefix engine audit` is recorded before and after (R7: 15 → 2 from the Stryker tree).

**Evidence before planning.** The plan's test parts come from the real 10.0.0 survivors, not from the
171 list, so the 10.0.0 run comes first. Every mutation run is local, never CI-gated, owned by the
orchestrator, and runs one at a time (A5 needs an unloaded machine):

1. **8.7.1 baseline** (running now) in the worktree, at the commit it started from (the baseline's commit).
2. **10.0.0 full run in a throwaway clone.** `git clone` the repository into a `mktemp -d` and check out
   the baseline's commit detached. In the clone, run the R1 install command, then `cd engine && npm ci`
   (the R1 check), then `npm --prefix engine run mutation`.
   `git -C <clone> diff --stat` must show only `engine/package.json` and `engine/package-lock.json`. That
   proves the source and test tree is the baseline's. The worktree is not touched.
3. **Comparison A1-A6** (below) over the two clear-text reports.
4. **Planning.** One part per cluster of real survivors among the 171 (Survived + NoCoverage after step
   3), grouped by source module. Each part's context block carries its mutants' `file:line:col`, the
   original statement, the class from the equivalence guidance above, and the covering suite. A part adds
   kill tests (red against the mutant applied by hand in a `mktemp -d` copy, green on the tree) or
   records the candidate-5 disposition. Shared-set regressions found by A2 that are real are blockers,
   not parts.
5. **In-tree bump + final validation.** The last part runs the R1 install in the worktree, then the
   full in-tree `npm --prefix engine run mutation` on 10.0.0. If its lockfile differs from the clone's,
   the in-tree lockfile and the in-tree run are the record. Then the R4 proof runs, the BACKLOG item is
   closed, and `ci.sh` runs.

| Condition | Value |
|---|---|
| Node | 22.22.3, every full run. 8.7.1 cannot score on 24.x |
| Config | `engine/stryker.conf.json` unchanged, `concurrency: 2`, same machine, no other run in parallel |
| Command | `npm --prefix engine run mutation`, clear-text output kept to a file per run |
| Compared | total mutants; Killed / Survived / Timeout / NoCoverage / RuntimeError / CompileError / Ignored counts; mutation score (total and covered), over the shared set and over the whole run; the per-file set of Survived + NoCoverage mutants, keyed by `file:line:col` + mutator; wall time |
| Shared-set split | clear-text lists only Survived and NoCoverage mutants by location. Shared-set survivors are the whole-run list minus the 171 keys. Shared-set detected = whole-run detected − (171 − the 171's Survived − the 171's NoCoverage), which assumes the 171's remainder is detected. A 10.0.0 run may append `-- --reporters clear-text,progress,json` instead. That is CLI only, leaves the config untouched, and writes to the gitignored `reports/`, which gives every mutant's status by key. If any of the 171 is a RuntimeError, only the JSON shows it |

Pass criteria. Step 3 applies them to the clone run. The step 5 run must meet them too, against the same
8.7.1 baseline, with A6 at zero open survivors. In step 5, A1's total is also reduced by the mutants on
any statement deleted under candidate 5, and those mutants are listed by key under A4. Source edits under
candidate 5 (a comment line, a deleted statement) shift the keys below them in that file. For those
files, step 5 matches mutants through the `git diff -U0` hunks of the edit, or by mutator + replacement +
original text, never by raw `line:col`.

- A1: **mutant total.** 8.7.1 = 10141 (instrumenter probe, re-run on this tree). 10.0.0 total =
  baseline total + 171. If the baseline run shows another total, the probe's options differ from the
  run's, and the runs' own totals are used instead, with the +171 delta still required.
- A2: **no unexplained new survivor in the shared set.** Every mutant outside the 171 that is Killed or
  Timeout in the baseline and Survived or NoCoverage on 10.0.0 is hand-verified against its full
  covering test set. Apply the mutant by hand in a `mktemp -d` copy of the tree (never the worktree), run
  the covering files with `node --test`, and record killed or not. The tap runner can mis-collect a
  file, so a mutant that the full set kills is a runner artefact and is recorded as such. A mutant the
  full set does not kill is a real regression and a blocker. Each verdict gets one line in the handback.
- A3: **score over the shared set.** No drop that A2 does not explain. Timeout ↔ Killed moves are
  timing noise: both count as detected, so they leave the score unchanged and need no triage. The
  whole-run score is reported, never compared with 8.7.1 (ADR-570: the denominator differs).
- A4: **mutants that disappear.** Survivors present in the baseline and absent on 10.0.0 are listed,
  not gated.
- A5: **wall time.** Both durations recorded and reported, never gated. One sample each cannot
  separate the tool from machine noise, and 10.0.0 runs 171 more mutants.
- A6: **the 171, triage in scope (R9).** Reported apart from the shared set, killed / survived per file
  and per guidance class. In step 3 every Survived or NoCoverage mutant among them becomes a planned kill
  or a candidate-5 disposition. In step 5 none of them may be Survived or NoCoverage without its
  recorded disposition.
- If a dry run dies with "Worker exited unexpectedly", narrow the test corpus per mutated file with an
  override config in a `mktemp -d`, passed as a positional argument. Do not retry.

**R4 proof (Node 24).** In step 5, under Node 24.11.0, run a narrowed mutation run: an override config
in a `mktemp -d` with `mutate: ["engine/src/cli-io.js"]` and `tap.testFiles: ["engine/test/cli-io.test.js"]`.
It passes if the killed count equals the same narrowed run on 22.22.3. The tap-runner `dist/` in 10.0.0
is byte-identical to 9.6.1's (pinned), so the runner-output table above holds for the version that ships.
`cli-io.js` carries 1 of the 171 (`cli-io.js:53` `io.stderr.write(message)`), and both narrowed runs
include it.

**Re-running the pins.** Every probe above is recorded by method (throwaway install + audit, schema
diff, mutant-set diff, runner-output table), so a later patch bump can repeat it.
