# Design — codex rules deploy step: a *Configure* step that copies `craft.rules` and verifies the copy

> Brief: no install step deploys `adapters/codex/craft.rules` to `$CODEX_HOME/rules/`, so the
> execpolicy layer the README lists is absent on every documented install. Add one *Configure* step
> that names the copy and how the operator verifies it, pinned in
> `adapters/codex/test/native-surface.test.js`. Docs and pin only: no installer code, no new bin.
> Status: draft → self-reviewed ×3

---

### Pinned matrix (2026-10-16, codex-cli 0.162.1)

The designer ran these in a throwaway `<probe>` directory with `CODEX_HOME=<probe>/ch`. That home
holds no `auth.json`, so no session can reach a model. The isolation proof is
`find ~/.codex -newer <probe>/marker` → **0 entries**.

**Load detector.** The probe uses a *malformed* file: `craft.rules` with its last line removed. A
loaded file then makes `codex exec` exit 1 at startup with `Error loading rules: <path>:16:
starlark error … Parse error`, before any session starts. A file that is not loaded lets codex go
on to the model call, which shows as the session header followed by
`401 Unauthorized … wss://api.openai.com/v1/responses` and then exit 1. Command:
`codex exec --skip-git-repo-check -s read-only -C <probe>/work "say hi" < /dev/null`.

| # | `$CODEX_HOME/rules/` layout | `codex exec` startup | Runs | Reading |
|---|---|---|---|---|
| L1 | `craft.rules` regular file (malformed copy) | `Error loading rules`, exit 1 | 3/3 | a copied file **is loaded** |
| L2 | `craft.rules` → symlink to a malformed file | session header, 401 ×N, no rules error | 3/3 | a symlinked file **is not loaded** |
| L3 | `rules` itself a symlink to a dir holding a malformed `craft.rules` | `Error loading rules`, exit 1 | 3/3 | a symlinked **directory** is followed |
| L4 | well-formed `craft.rules` copy plus a malformed `NOTES.md` | session header, 401 ×N, no rules error | 2/2 | only `*.rules` files are parsed |

**Verification commands.** These are file-level checks, one run each (`execpolicy check` is offline and deterministic). Command:
`codex execpolicy check --rules <file> git <sub>`, with the flag form taken from
`codex execpolicy check --help` (0.162.1): `Usage: codex execpolicy check [OPTIONS] --rules <PATH>
<COMMAND>...`.

| # | Target | `cmp adapters/codex/craft.rules <target>` | `execpolicy check … git push` |
|---|---|---|---|
| V1 | copied `craft.rules` | exit 0 | **exit 0**, stdout `"decision":"forbidden"`, matchedPrefix `git push` |
| V2 | symlink to the committed bytes | exit 0 | exit 0, `"decision":"forbidden"` (follows the link) |
| V3 | copied `craft.rules`, `git status` | — | exit 0, `{"matchedRules":[]}` |
| V4 | absent file | exit 2, `No such file or directory` | exit 1, `failed to read policy … No such file or directory` |
| V5 | empty file (`execpolicy` result: prior record rows, 2026-10-16) | exit 1, `EOF on <file>` | exit 0, `{"matchedRules":[]}` |

Findings that shape the design:

- **A file symlink is a silent void.** L2 together with V2: codex does not load the symlink, yet
  both file-level checks pass on it. No verification the README could show detects this layout. The
  `ln -s` habit the README teaches for skills (L59) would carry over and produce exactly that
  layout.
- **`execpolicy check` signals through stdout, not the exit code.** It exits 0 for both `forbidden`
  and no match (V1, V3, V5), so a verification built on it must read `"decision":"forbidden"`.
- **Neither check proves that codex loads the file.** They are file-level checks. That a regular file
  under `$CODEX_HOME/rules/` is loaded rests on L1, not on the verify command.

## Requirements

1. `adapters/codex/README.md` `## Configure` contains a step that copies `adapters/codex/craft.rules` to
   `$CODEX_HOME/rules/craft.rules` (default `~/.codex/rules/`), created if absent, run from the
   repository root.
2. The same step names the verification the operator runs on the copy, and says what passing looks
   like.
3. The step says to copy, not symlink, and gives the reason: a symlinked file is not loaded, yet it
   passes the file-level checks. The observation carries its codex version (0.162.1).
4. The step says no codex error flags a void copy: an empty or comments-only file parses cleanly
   and forbids nothing.
5. The step says to re-run the copy and the verification whenever `adapters/codex/craft.rules`
   changes, because a stale copy still parses and may forbid less.
6. `git grep 'CODEX_HOME/rules' -- adapters/codex/README.md` returns at least one line.
7. The README does not name `assertRulesIntegrity` (ADR-600) and passes every existing hygiene scan in
   `native-surface.test.js`.
8. New pins in `describe('README.md — honesty pins'` go RED against today's README and GREEN after
   the edit.
9. `adapters/codex/craft.rules`, `src/`, `bin/` and every other test file are unchanged.

## Design

### README — one new paragraph and one fenced block under `## Configure`

The new text goes after the existing `config.template.toml` paragraph. Draft wording follows; the
plan may polish it, but the pinned tokens are marked.

````markdown
Deploy the execpolicy rules file: copy `craft.rules` into `$CODEX_HOME/rules/`, the
directory codex loads `*.rules` files from. From the repository root:

```
mkdir -p "${CODEX_HOME:-$HOME/.codex}/rules"
cp adapters/codex/craft.rules "${CODEX_HOME:-$HOME/.codex}/rules/craft.rules"
cmp adapters/codex/craft.rules "${CODEX_HOME:-$HOME/.codex}/rules/craft.rules"
```

`cmp` printing nothing and exiting `0` is the verification: the deployed copy is
byte-identical to the committed file. No codex error flags a bad copy — an empty or
comments-only file parses cleanly and forbids nothing — so do not skip it. **Copy, do
not symlink**: on codex 0.162.1 a symlinked file in `$CODEX_HOME/rules/` is not
loaded, yet it passes `cmp` and `codex execpolicy check`, both of which follow the
link. Re-run all three lines whenever `adapters/codex/craft.rules` changes; a stale
copy still parses and may forbid less.
````

The pinned tokens are `$CODEX_HOME/rules/` in prose, the `cp adapters/codex/craft.rules …/rules/craft.rules`
line, the `cmp adapters/codex/craft.rules …/rules/craft.rules` line, and the phrase "do not symlink".
The verify command depends on Candidate 2. If (b) or (c) is chosen, the block gains
`codex execpolicy check --rules "${CODEX_HOME:-$HOME/.codex}/rules/craft.rules" git push` and the
prose says to look for `"decision":"forbidden"` on stdout.

Edge behaviour:

- **`CODEX_HOME` unset.** `${CODEX_HOME:-$HOME/.codex}` resolves to codex's own default, the one the
  README states at L88 and `trust-hook-main.js` `resolveConfigPath` uses (`CODEX_HOME`, then
  `HOME/.codex`). A bare `$CODEX_HOME` would expand to `/rules`, and `mkdir` would fail there,
  loudly. The default form avoids that failure rather than relying on it.
- **A checkout path with spaces.** Every operand is relative or double-quoted.
- **The operator's own `*.rules` files** sit beside `craft.rules` untouched. The step writes one named
  file and does not replace the directory.
- **A `cmp` mismatch** prints `differ: char N, line M` and exits 1. An absent target exits 2 with
  `No such file`. In both cases a re-copy is the remedy, and the prose does not need a branch for
  each.

### Test — pins in `describe('README.md — honesty pins'`

The scope depends on Candidate 3. Under the recommendation, `native-surface.test.js` gains a
test-local `sectionAfter(text, heading)`, mirroring `test/community-scaffolding.test.js` L24, and these
`it`s, sliced to the `## Configure` body:

```js
const CONFIGURE_HEADING = '## Configure';

it('Given the Configure section of README.md, when scanned, then it names $CODEX_HOME/rules/ as the deploy target', …
  assert.match(sut, /\$CODEX_HOME\/rules\//));
it('Given the Configure section of README.md, when scanned, then it copies adapters/codex/craft.rules into the rules directory', …
  assert.match(sut, /cp adapters\/codex\/craft\.rules \S*\/rules\/craft\.rules/));
it('Given the Configure section of README.md, when scanned, then it verifies the copy byte-for-byte against the committed file', …
  assert.match(sut, /cmp adapters\/codex\/craft\.rules \S*\/rules\/craft\.rules/));
it('Given the Configure section of README.md, when scanned, then it says to copy and not symlink the rules file', …
  assert.match(sut, /do not symlink/i));
// whole README, negative: a symlinked rules file is silently not loaded
it('Given every ln -s README.md shows, when its target is inspected, then none lands in a rules directory', …
  assert.doesNotMatch(readme, /ln -s[ \t]+\S+[ \t]+\S*\/rules\b/));
```

The negative regex leaves the skills line (`… $CODEX_HOME/skills/<name>`) alone. Every `it` here is
RED against today's README, except the negative pin, which is green today and guards against
regression; the bare-shorthand pin at L371–382 sets that precedent. If the heading is missing,
`sectionAfter` returns `null`, and the test asserts non-null first, so a renamed heading fails
loudly instead of passing on an empty match.

## Test strategy

- **RED first.** Add the four `## Configure`-scoped `it`s and the `sectionAfter` helper to
  `adapters/codex/test/native-surface.test.js`, then run
  `node --test adapters/codex/test/native-surface.test.js` and pipe the output to a file. The four
  must fail and the negative pin must pass.
- **GREEN.** Edit `adapters/codex/README.md` `## Configure`, then re-run the suite. All pins must
  pass, along with the existing hygiene scans (`PROVENANCE_REF`, shell injection,
  `${CLAUDE_PLUGIN_ROOT}` shim) and the twelve existing honesty pins.
- **Mutation lens on the pins.** Do these by hand once and do not commit them: delete the `cmp`
  line → the verify pin goes RED; move the copy step under `## Guard` → the section-scoped pins go
  RED; turn `cp` into `ln -s` on the rules line → the negative pin goes RED.
- **Gate.** `bash scripts/ci.sh`, which runs the README drift and design-lint gates over this doc and
  the 73 count.
- **No live codex in tests (ADR-261).** The matrix above is recorded evidence. Re-running it is a
  developer-run, on-demand probe in a throwaway `CODEX_HOME` with no `auth.json`.

## Out of scope

- **Installer code or a new bin** (`check-rules`, a deploy subcommand of `trust-hook.js`): the brief
  limits this to docs and pins, and ADR-599 rejected a dedicated bin.
- **Calling `assertRulesIntegrity` from anywhere**: ADR-599 keeps it on demand.
- **Editing the Guard table or bullets** (for example "absent unless deployed"): the brief names one
  *Configure* step.
- **Moving `craft.rules` into a rules-only directory** to make a directory symlink safe: it is a
  file move, and its generator and test paths would change with it.
- **Ticking the BACKLOG entry**: the documentation phase does that.
- **Proving that a well-formed copy blocks a live command** (`codex exec` → `git clean` survives): the
  0.162.1 re-probe already pinned it (record L560, row 5a). It needs an authenticated session, and
  this change does not alter it.
