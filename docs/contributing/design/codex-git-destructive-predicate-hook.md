# Design — codex-git-destructive-predicate-hook

> Brief: compose the destructive-git predicate into the codex PreToolUse guard hook, so
> `git -C . push` and `git --git-dir=… push` stop bypassing the binding, and decide whether codex
> also takes copilot's plain-command gate (BACKLOG "Compose the destructive-git predicate into the
> codex hook").
> Status: draft → self-reviewed ×3

## Context

### What codex enforces today

Timing, sampled (not a worst-case proof): `gitDestructivePredicate` on adversarial shapes up to
57 344 characters (`git -c ` repeated, `git push x; ` repeated, nested `$(`, `eval` chains,
`bash -c` chains) took 0.1–50 ms; review later measured about 190 ms at the 131072-character
tokeniser cap (`git ` repeated), linear in length, with no super-linear path found. The real hook process, cold, over the 0.162.1 payload: 75–78 ms
end to end (three runs). The tokeniser caps input at `MAX_COMMAND_LENGTH = 131072`
(`shell-tokeniser.js:15`) and `gitInvocations` caps argument-reading anchors at 256.

### Does `bash -lc 'git push'` reach the predicate?

Yes. `shell-tokeniser.js` `reparsedWords` re-parses the operand of a `SHELL_NAMES` word
(`sh bash zsh dash ksh`) followed by a cluster containing `c` (`-lc` matches `CLUSTER_SHAPE` and
`COMMAND_FLAG`), and `eval` operands (`evalWords`). The predicate denies `bash -lc 'git push'` with
the push reason. With a dynamic flag (`C=-c; bash $C 'git push'`) the recursion does not fire, and
the predicate allows it; only the gate denies it.

## Requirements

- R1. The codex hook denies every command the reference predicates deny on copilot's Bash path:
  `gitDestructivePredicate` (push, `reset --hard`, forced branch delete, `clean` without
  `--dry-run`, config-channel and inline-alias injection, indeterminate subcommands) and the
  ext-diff predicate, judged over one parse. `git -C . push origin main` and
  `git --git-dir=.git push origin main` fed as the real 0.162.1 payload make the hook process exit 2
  with the push reason on stderr and nothing on stdout.
- R2. Denials carry the shared predicates' reason text unchanged; the hook writes it as today
  (`craft-guard: <reason>` on stderr, exit 2).
- R3. Non-Bash behaviour is unchanged: `apply_patch` per-path containment, unmapped tools pass,
  malformed payloads fail closed through `decideGuard`'s catch.
- R4. Copilot's verdicts are unchanged: every existing copilot test passes untouched.
- R5. The `.rules` disclosure stays true: it still lists the three NO MATCH commands for that
  layer and also states that the PreToolUse hook denies them. `craft.rules` is regenerated, so
  `assertRulesIntegrity` and the byte-identity test still pass.
- R6. `adapters/codex/hooks.json` stays byte-identical (see Design, "What is not touched").
- R7. Docs that describe codex enforcement say what the hook now judges and which bypass classes
  stay open (depends on DC-2): `adapters/codex/README.md` guard section,
  `docs/contributing/specs/gate.md` "Codex binding", `docs/contributing/specs/codex-poc-record.md`
  (P1–P7 rows), and the BACKLOG entry leaves the Open list.
- R8. Under DC-2 (a) or (b): every command the gate denies on copilot is denied on codex with the
  same reason. Under DC-2 (a): a verdict that does not arrive by the deadline denies fail-closed.
- R9. `bash scripts/ci.sh` is green; the new engine module and the touched codex adapter meet the
  repo's mutation bar.

## Design

### Part 1 — one shared Bash verdict in `engine/src/guards/` (DC-1 a)

New module `engine/src/guards/git-bash-verdict.js`, a move of copilot's `bashBlock`:

```js
import { gitPlainCommandGate } from './git-plain-command-gate.js';
import { destructiveVerdictFor } from './git-destructive-predicate.js';
import { extDiffVerdictFor } from './git-ext-diff-predicate.js';
import { gitInvocations, judgeParsed } from './shell-git-invocations.js';

// Destructive git first, then ext-diff, over one parse of the command.
function parsedGitVerdict(command) {
  const parsed = gitInvocations(command);
  const destructive = judgeParsed(parsed, destructiveVerdictFor);
  return destructive.block ? destructive : judgeParsed(parsed, extDiffVerdictFor);
}

/** @param {string} command @returns {{ block: boolean, reason?: string }} */
export function plainGitCommandVerdict(command) {
  const gate = gitPlainCommandGate(command);
  return gate.block ? gate : parsedGitVerdict(command);
}
```

Exports follow DC-2: under (a)/(b) only `plainGitCommandVerdict` is exported (codex and copilot
both call it). Under (c) `parsedGitVerdict` is exported too, as `gitCommandVerdict`, for codex.
No export without a caller.

Copilot (`adapters/copilot/src/git-guard-adapter.js`): delete `bashBlock` (`:110`) and the four
imports it alone uses (`:7-10`); `copilotGuard` (`:126`) calls `plainGitCommandVerdict`. Behaviour
identical (R4). `toolCallGuard` stays untouched: it is still pi's, opencode's and cursor's Bash
path, and ADR-579 option 3 (every binding) was rejected.

### Part 2 — codex composes it (`adapters/codex/src/git-guard-adapter.js`)

```js
import { plainGitCommandVerdict } from '../../../engine/src/guards/git-bash-verdict.js';

/**
 * Bash: the shared git verdict; apply_patch: per-path containment; anything else: toolCallGuard.
 * @param {{ tool: string, tool_input: object, working_dir: string }} event
 */
export function codexGuard(event) {
  if (event.tool === BASH_TOOL_NAME) return plainGitCommandVerdict(event.tool_input.command);
  return WRITE_TOOLS.has(event.tool) ? decideWriteContainment(event, toolCallGuard) : toolCallGuard(event);
}

export function decideGuard(payload, guard = codexGuard) {
  try {
    return guard(adaptCodexEvent(payload));
  } catch {
    return { block: true };
  }
}
```

- `event.tool_input.command` is already a non-empty string: `bridgeExecutedCommand` throws
  otherwise, and the bridged `command ?? cmd` is the field the verdict reads. No new
  `commandOf`-style check is needed.
- The `guard` seam keeps its meaning (the whole event judge). The one test that injects it
  (`git-guard-adapter.test.js:306` `throwingGuard`) keeps working.
- `decideGuard`'s reasonless fail-closed stays. Its catch fires only on malformed payloads (absent
  `cwd`, non-string or empty command, unrecognised patch text); `gitPlainCommandGate`,
  `gitInvocations` and `judgeParsed` return verdicts on any string and never throw, so the
  composition adds no new path into the catch. The hook already turns a reasonless block into
  the fixed `denied (fail-closed)` line. Adding a reason would make the throw-site message
  mutants (annotated equivalent today) observable and need new tests, for a path codex's schema
  (`cmd` is a string) does not produce.
- Comment update in `bridgeExecutedCommand`: the payload was re-pinned on 0.162.1, which adds
  `session_id`, `transcript_path` and `hook_event_name`. They are ignored like the others.
- The `CODEX_TOOL_NAMES` comment and the module docblock change from "applies that predicate
  unmodified" to the composition above.

### Part 3 — the hook process (`adapters/codex/hooks/craft-guard.js`)

Under DC-2 (b) or (c): unchanged. It dynamically imports `../src/git-guard-adapter.js`, which now
statically imports four more engine modules. A failure to load any of them reaches the existing
catch → exit 2, already pinned by "a guard copy whose engine predicate cannot be resolved".

Under DC-2 (a): mirror copilot. Move `verdict-race.js` and `verdict-deadline.js` from
`adapters/copilot/src/` to `engine/src/guards/` (both bindings import them). Add

headroom. An operator `timeout` below the deadline would still fail open (P4); the README says so.

### Part 4 — disclosure, rules file, docs

`DISCLOSURE_COMMENT` becomes (the `/git -c/i` and `/fail open/i` assertions still hold):

```
# Defence-in-depth only -- not a security boundary.
#
# Known bypasses of this layer (verified, not hypothetical): interposed global
# options defeat the prefix match entirely. `git -C . push`, `git --git-dir=.git
# push`, and `bash -lc 'git push'` all NO MATCH here -- matching is

# entry point it either refuses to start or skips the rules and runs
# commands. Treat it as fail open.
```

### What is not touched

- `adapters/codex/hooks.json` and the `config.template.toml` hook block: byte-identical. Codex
  trusts a hook by `currentHash` (`hook-trust.js`). Whether the top-level `description` is part
  of that hash is unprobed, and an untrusted hook silently no-ops (`codex-poc-record.md:140`). A
  wording change is not worth that risk. To prove it harmless: `hooks/list` before and after a
  description edit in a throwaway authenticated `CODEX_HOME`, compare `currentHash`.
- `toolCallGuard`, pi, cursor, opencode, antigravity (ADR-579 option 3 rejected).

### Edge behaviour

| Input | Verdict |
|---|---|
| Bash payload with `cmd` only (no `command`) | judged on `cmd` (bridged), as today |
| Bash payload, `command` empty / non-string / array | `decideGuard` catch → `{ block: true }` → `denied (fail-closed)` (unchanged) |
| Command the tokeniser cannot parse, no `git` in it (`echo "$(`) | denied with the parser reason, as today (the ext-diff path already parsed every command) |
| Command over 131 072 characters | denied with the tokeniser's length reason, as today |
| A `git` word inside `apply_patch` text | not judged by git predicates (write tool), as today |
| `shell` argument naming bash 3.2 | invisible to the hook (P3); the gate (DC-2 a/b) denies the constructs whose meaning depends on it |
| Hook exceeds codex's `timeout` | fails open (P4); default above 90 s (P5) |

## Test strategy

`sut` variable; titles printable ASCII only (no `⏎`, NEL, U+2028 or invisible characters; Stryker's
tap dry run rejects them), so the matrix's newline rows are built with `\n` in the body, never in
the title.

`scripts/ci.sh` discovers it as a `*.test.js` and runs it.

Harness reuse: move the generator, stub-git tree, shell runner and argv oracle out of
`engine/test/guards/shell-git-invocations.differential.test.js` into
`engine/test-helpers/git-differential-harness.js`. That covers `mulberry32`, `createGenerator`,
`generateCommands`, `withTree`, `runInShell`, `mapPool`, `parseArgvLog`, `judgeArgv`/`oracleVerdict`,
`secondBash`, `findOnPath` and the `RESIDUAL_MARKER` protocol. The engine fuzz imports it; its
"generated twice → identical" row proves the move changed nothing. `engine/test-helpers/` is not
mutated.

Oracles, one per consumer:
1. **Shell.** Each generated command runs under `/bin/bash` (3.2; the model can pick it, P3),
   `/bin/zsh` (codex's default tool shell here, P1), and the first bash ≥ 5 on `PATH` (skipped
   when absent). The stub `git` is the only git reachable, and it logs argv. The verdict under
   test is the in-process `decideGuard(fixture(command))`. Failure: the oracle saw a
   destructive or ext-diff argv (after the residual-marker filter) and the verdict allowed it.
   False blocks are reported as `t.diagnostic` counts, not failures, because the gate denies on
   purpose.
2. **Node.** For every generated command, spawn the real `craft-guard.js` (pool 8, 5 s spawn
   timeout) with `JSON.stringify(fixture(command))` on stdin, `CRAFT_ROOT` set and unset. Assert
   exit 2 ⇔ in-process `block`, and stdout empty on both. This catches divergence between the
   string node decodes from the JSON payload and the string the in-process test judges
   (U+2028/U+2029, NUL, lone surrogates, very long payloads), and any load-path difference.

Seeds and cap reuse `GUARD_FUZZ_SEEDS`/`GUARD_FUZZ_COUNT` (default 400 commands, one seed). The
node leg is ≈ 400 × 78 ms / 8 ≈ 4 s. Generated commands never appear in test titles, only the seed.
Mismatches are classified by direction (fail-open / fail-closed) and recorded in the review
findings.
